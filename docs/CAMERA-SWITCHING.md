# 分屏定位、镜头构图与游戏切换

## 镜头栏的单页结构

本关画面规则 → 镜头清单 → 当前镜头取景 → 特殊控制区域。清单只保留一份，正常游玩、额外视角和地图总览显示为用途标签；单击只选择，双击清单或点击编辑取景进入主画布。数字默认收在精确参数，名称、用途、锚点引用和卷轴位于关联与原生设置。

规则分屏的起点、尺寸和屏数放在本关画面规则的分屏参数中；普通相机编辑与分屏黄框编辑分别标识。特殊控制区域单独折叠，无区域时不显示空分类。折叠、选择、搜索及面板滚动只记在本机。新增额外视角从所选玩法镜头复制构图，或从主镜头开始，不破坏原相机。


## 先区分两个入口

- **导航下拉 → 镜头构图／分屏构图**：与对应编辑入口使用相同的位置、观察点、上方向、视角和构图比例。选择只查看，不保存镜头；拖动后继续自由导航。总览不再临时改成另一个俯视角度。
- **属性 → 编辑镜头／编辑普通镜头**：编辑当前 Camera_Control 相机对象，不沿用上次选中的分屏，不自动改变游戏运行方式。
- **分屏卡片 → 编辑镜头**：进入所选屏的取景，保留画布黄线和左侧可点击的布局选择图，继续切换其他屏。

在选择工具下，单击分屏中的地面或空白处，边界高亮后点击“编辑镜头”；也可以双击该屏。自由编辑时点到物件仍先选择物件，拖动空白处仍可框选。分屏取景中可点击黄框或选屏图切换，不产生工程修改。分屏卡片及选屏图均有“移动边界”，点下直接显示整体移动柄，无需 W。画布上方的网格图标控制分屏边界，默认开启，简洁模式也可使用；关闭后不进行虚拟分屏选择。

规则分屏共用一套取景参数，按网格平移。选中第 (1, 0) 屏，是从这屏查看和修改整套镜头，不是创建“进入这屏时调用另一台摄影机”的触发器。点击“完成镜头编辑”或按 Q 恢复原自由视角。静态构图不验证游戏的动态过渡、特殊区域限制、探索范围自适应或额外视角解锁。

分屏构图导航按完整规划列出分屏，包括没有地形的屏；例如 3 列 × 2 行列出 6 屏。自动模式覆盖设计范围内的整套网格，不再只列有地形的屏。导航旁显示总屏数，超过 500 屏时分页，继续向后可到达最后一屏。定位高度使用当前编辑高度，显示切换不修改原生地形或分屏参数。

普通、分屏及总览镜头编辑均提供 XYZ 平移、XYZ 旋转及完整方向立方体对齐。中键移动、右键旋转；G/R 后按 XYZ 设置世界轴约束。完整位置、观察点和上方向随工程保存，不再钳制为 5°～89° 或清除侧倾。分区 X/Y 切换当前取景屏，修改同套镜头后其他屏按网格平移。

原游戏规则分屏仍会按房间中心和距离重算姿态：可表达的构图写入对应原生距离与偏移，其余自由姿态保留到工程及原生相机位置／旋转字段，并在画布与构建检查中提示运行差异。未修改游戏程序，不将六轴可编辑等同于原游戏已支持任意分屏旋转。

布局只绘制配置的横纵屏数；选中即显示整套布局中心的 X/Y 移动柄，无需 W，移动和撤销后继续显示。“编辑整套镜头”按钮已移除；所选分屏卡片上的“编辑镜头”直接传入该屏坐标和镜头，采用它当前的取景。整体移动不改地形和循环范围，自动布局在移动提交后固定当前屏数；取消及撤销可恢复自动状态。横纵数量是编辑规划，角色走出矩形后仍使用原生网格取景，不自动改为总览或另一台镜头。

数字参数在当前输入框即时预览并自动提交；同一段连续输入合并撤销。游戏中的分层界限与摄影机高度不是一个参数：原作可根据角色所在玩法层选择镜头，当前编辑器保留这些导入配置，尚无完整的“角色 Z 超过某值 → 指定镜头”创建向导。

## 多台镜头如何在游戏中使用

可以新建多个“玩法镜头”，但创建不等于配置完成。辅助镜头也属于这个类别，通过“镜头用途：正常游玩／卷轴解锁”区分；同一高度放多台主镜头不会自动形成进入区域切换的触发器。

1. **规则切屏**：设置网格起点和每屏格数，角色跨屏时游戏自动平移取景。
2. **不同高度的玩法镜头**：原版通过世界层及主镜头选择处理。保留导入关的层边界、主镜头和限制区域。不要把同层新增多台主镜头理解成任意房间的独立角度触发。
3. **额外视角卷轴**：在素材库“世界”找到“视角卷轴”（View_Giver）。属性的“卷轴镜头关联 → 额外视角”直接选择镜头；选择主镜头会复制为辅助视角，保留原镜头。原生仍通过 `viewpoint_name` 与辅助镜头的 `entity_name` 对应，例如 `side` 或 `top`；菜单自动处理名称及用途。游戏获得该视角后，通过游戏的切换视角操作使用，按键以游戏键位设置为准。
4. **地图总览**：卷轴的 `map_overview_id` / `map_overview_id_2` 关联总览镜头。总览与额外侧视／俯视不是同一个配置字段。

镜头面板的“游戏中如何切换镜头”列出当前加载内容里的卷轴与镜头对应关系。卷轴属性提供解锁视角、地图总览、第二地图总览三个下拉，只列对应类别的镜头。通过下拉建立的普通视角关联随工程保存目标 ID，构建时解析为最终原生名称；改名后继续对应同一相机。清除、批量关联和自动复制均可一步撤销。所属存在组属于高级，不参与镜头选择。

`camera_z_lock` 的目标是确定观察高度的物件，目标不必是摄影机。其附加浮点参数参与区域选择，不是要锁定的 Z 数字。不能将它作为任意指定摄影机的房间触发器。

## 相机用途与控制区域

相机从镜头清单的 ＋ 创建；区域从特殊控制区域的 ＋ 创建，不再混在一个下拉里。

| 清单／类型 | 用途 |
| --- | --- |
| 正常游玩 | 默认游玩使用的主镜头；多高度主镜头继续遵循原生层规则。 |
| 额外视角 | 可由卷轴解锁的辅助视角，新建时复制当前玩法镜头的构图。 |
| 地图总览 | 查看地图全貌，也可由卷轴解锁，不代表默认获得。 |
| 观察高度区域 | 通过关联物件确定镜头参考高度，不限制角色高度。 |
| 分屏取景限制 | 限制原生分屏取景范围，不生成分屏网格。 |
| 总览覆盖范围 | 总览使用的覆盖区域，本身不是摄影机。 |

## 新建时出现编号冲突

旧版本可能把已删除相机的编号分配给后放置的卷轴等物件。构建先回放玩法物件，再回放相机历史，因而报“新增相机 ID 冲突”。alpha.8 的本地修正让两类分配共同保留历史编号，组合与批量放置也检查完整编号范围。

对于已经存在的这类工程，只在内存回放时为明确已删除的旧相机分配临时编号，并同步其依赖、引用和删除操作。不改写原工程或玩法物件 ID；仍然存活的编号冲突继续报错，不覆盖物件。

## 本次修正和验证界限

按 Steam Build 26466613 的原生结构及构造逻辑修正省略值：FOV 35°、高度 19、南向距离 12、平移速度 0.35、观察点南向偏移 0。空白关已经显式保存的 45°不改写。显式值始终优先。

分屏预览读取观察点南向偏移，窄画幅按原生的 16:9 水平视野规则换算；“框住当前分屏”只适应当前屏内的玩法范围。未修改原版记录保持原样。

自动检查覆盖界面入口、取消、选屏不修改工程、字段读写及构图数学；本轮没有启动游戏。多高度自动选择、卷轴获取与切换、区域过渡及最终画面由用户在隔离测试战役中核对。
