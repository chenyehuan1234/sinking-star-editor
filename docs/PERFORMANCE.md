# v0.7.9 性能记录

本轮为可重复的自动基准，不能替代用户对完整编辑器手感或游戏机制的验收。没有同条件的旧版基线，因此不宣称相对旧版的提升倍数。

## 条件与范围

Windows x64，Intel Core i9-14900HX，Electron 45，1366×768 隐藏的独立 Chromium 测试窗口；与用户配置、存档及当前窗口隔离。100／1,000／5,000 个 Rock 使用简化几何代理；另测原版 `green_metamirror` 的 2,665 条实体及实际模型。代理场景不能代表 5,000 个复杂原生模型的开销。

每个场景取 30 次选择、120 次本地拖动帧反馈、30 次半透明代理预览。选择／预览反馈测到下一次动画帧；拖动反馈逐帧测量，渲染 CPU 记录 `renderer.render` 的时间，未做 GPU 栅栏测量。首次阶段包含该场景的资源准备，后续统计为预热结果；操作系统磁盘缓存未清空，各场景共用进程资源缓存。内存是渲染进程 JS 堆的阶段净变化，受垃圾回收影响，不是整个编辑器的总占用。

## 实测（毫秒；内存 MB）

| 场景 | 首次准备 | 选择 P95 | 拖动反馈 P95 | 拖动渲染 CPU P95 | 代理预览 P95 | JS 堆净变化 |
|---|---:|---:|---:|---:|---:|---:|
| 100（简化物件） | 155.2 | 19.2 | 18.1 | 0.4 | 32.6 | 5.8 |
| 1000（简化物件） | 35.5 | 20.1 | 18.0 | 1.4 | 33.7 | 6.1 |
| 5000（简化物件） | 113.8 | 24.7 | 18.3 | 5.3 | 32.5 | 39.4 |
| 2665（原版多高度） | 303.9 | 39.4 | 17.8 | 1.2 | 27.8 | 16.5 |

本轮这些预热场景达到选择／代理预览 100ms、拖动反馈 33ms 的目标。该结论只覆盖上述脚本路径；完整应用的新原生物件放置、超大组合与低配置电脑仍需用户测试。原版关首次准备 303.9ms，首次资源加载仍可能出现等待。

## 原生预览处理

独立后台线程对同一原版关执行 30 次已提交位置修改：首次请求 514.3ms，预热往返 P95 72.0ms（包括请求、原生处理和差量传输）。首次全量 JSON 约 2,899,364 字符，常规位置修改差量 P95 1,879 字符。复杂操作可完整重建；差量传输不等于只运行几行原生解析。

此独立 Node 测试进程及线程的 RSS 从 64.4MB 到 619.1MB，包含游戏包、程序反射、缓存和工作线程；预览缓存会保留多份修订，内存仍有优化空间。该数字不是整个 Electron 编辑器的实测总占用。

## 自动界面与事务检查

实际 StudioApp 独立测试中，选择、创建分组、撤销分组均没有新增预览请求；一次属性提交只有一次原生预览请求。检查分组保存、锁定删除拦截、命令同义词与键盘焦点。在 1366×768、1920×1080 及 Electron 150% 页面缩放下检查画布和命令窗口并审阅截图；页面缩放不等同于完整的 Windows 多显示器 DPI 验收。

视口脚本确认 300ms／80ms 连续微移、释放后一次提交，以及 Esc／失焦后恢复原位且计时器不补交。原生数据回归与上述界面检查不启动游戏，不证明实际通关或特殊机制正确。

## 复现

安装开发依赖并完成 `npm run build`。设置 `SINKING_STAR_GAME` 指向自己的 Steam 游戏目录，然后分别运行：

```powershell
node scripts/benchmark.mjs
npx tsx scripts/benchmark-native.ts
node scripts/ui-check.mjs
```

结果写在本机 `workspace/benchmark-v079` 和 `workspace/ui-check-v079`，不纳入公开源码；不要同时运行多组基准，以免互相争用。基准不部署测试副本，不连接或切换游戏战役。
